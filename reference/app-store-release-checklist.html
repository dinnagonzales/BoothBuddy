App Store Release Checklist

Simple kid-friendly app · Expo path · 3-week target

Start Apple Developer enrollment on Day 1. Everything else waits on that account.

Phase A — Accounts (Days 1–2)

  1. Enroll in Apple Developer Program ($99/yr) — legal name must match ID exactly
  2. Create free Expo account at expo.dev
  3. Install EAS CLI: npm install -g eas-cli

Phase B — Build app (Days 1–10)

  1. npx create-expo-app — TypeScript template
  2. Set unique bundleIdentifier in app.json (e.g. com.yourname.appname)
  3. Build MVP: local SQLite + share-sheet PDF export + parental gate
  4. No third-party analytics or ads (Kids Category rule)
  5. Write privacy policy URL (even “we collect nothing” needs a page)
  6. eas build:configure then eas build --platform ios --profile production

Phase C — App Store Connect (Days 8–12)

  1. Create app record in App Store Connect (name, bundle ID, SKU)
  2. eas submit --platform ios --latest
  3. Test on TestFlight (build processing ~2h, beta review ~8h)
  4. Upload screenshots (6.7" iPhone required; iPad if universal)
  5. Fill App Privacy questionnaire (likely “Data Not Collected”)
  6. Select Kids Category + age band (5 & under / 6–8 / 9–11)
  7. Add review notes: demo flow, parental gate location, local-only data

Phase D — Submit & launch (Days 12–21)

  1. Submit for App Store review (Tuesday/Wednesday morning ideal)
  2. Wait: new app typically 2–5 days; Kids Category may add time
  3. If rejected: fix → resubmit (each cycle restarts the clock)
  4. On approval: release manually or set auto-release
