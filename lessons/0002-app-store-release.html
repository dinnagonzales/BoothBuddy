How releasing a simple app on the App Store works

You want the app live in ~3 weeks. This lesson maps the pipeline, the clocks that matter, and an honest timeline.

The pipeline (four stages)

Releasing is not one button. It is four separate stages, each with its own wait time:

1. Enroll — Pay $99, join Apple Developer Program
Typical: 1–2 days. Apple says up to 48 hours. Can stall if name/ID mismatch.

2. Build — Turn your code into a signed .ipa binary
With Expo EAS: ~20–40 min cloud build after config. First time adds credential setup.

3. Submit — Upload binary + fill store listing in App Store Connect
Metadata, screenshots, privacy labels, Kids Category settings. You do this in a web portal.

4. Review — Apple human checks guidelines compliance
New apps: often 2–5 days in 2026. Kids Category gets extra scrutiny. Rejection = clock resets.

As a web developer, think of it like: buy hosting (Developer account) → build production bundle (EAS) → fill CMS fields (App Store Connect) → QA gate (Apple review).

Your path: Expo + EAS (no Mac required)

Since you already write React, Expo Application Services (EAS) is the shortest route. You do not need Xcode on your desk — Expo's Mac cloud VMs compile the native binary.

What Apple checks for kid apps

Choosing the Kids Category triggers stricter review — but for your local-only design, that is mostly an advantage:

  • No third-party analytics or advertising SDKs
  • Privacy policy required (can honestly say "data stays on device")
  • Parental gate before email/share, purchases, or external links
  • Age band selection (5 & under, 6–8, or 9–11)

Review notes matter: tell the reviewer where the parental gate is and that there is no login or server. See Guideline 5.1.4.

Can you make 3 weeks?

What to cut if time runs short

  • Skip weekly/monthly sheets — ship daily export only
  • Skip scheduled notifications — manual "Share" button first
  • Skip iPad layout — iPhone-only is fine for v1
  • Do not add accounts, sync, or in-app purchases in v1

Steps — your ordered checklist

  1. Today: Enroll in Apple Developer Program ($99/yr). Create Expo account.
  2. Day 1–2: npx create-expo-app@latest → set bundleIdentifier, app name, icon in app.json.
  3. Day 2–8: Build MVP — local SQLite, one kid flow, PDF share sheet, parental gate. No analytics SDKs.
  4. Day 6: Publish privacy policy page (GitHub Pages or your site). Required even if you collect nothing.
  5. Day 8: npm i -g eas-cli → eas login → eas build:configure.
  6. Day 9: eas build --platform ios --profile production — let EAS manage Apple credentials.
  7. Day 9: Create app in App Store Connect (match bundle ID exactly).
  8. Day 10: eas submit --platform ios --latest — binary lands in TestFlight.
  9. Day 10–11: Install via TestFlight on a real iPhone. Fix crashes before public review.
  10. Day 11–12: Upload screenshots, write description, set App Privacy to "Data Not Collected", pick Kids Category + age band.
  11. Day 12: Write Review Notes (parental gate steps, local-only, how to test share flow).
  12. Day 12–13: Submit for Review — prefer Tuesday or Wednesday morning.
  13. Day 13–18: Wait. If rejected, fix the specific issue and resubmit same day.
  14. On approval: Release to App Store. Share your apps.apple.com/app/id… link.
